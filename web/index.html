📘 Guía Práctica: Cómo Conectar Android y la Web con MQTT (EMQX Cloud)

Explicación detallada línea por línea de la arquitectura, puertos, permisos, código de Android (MainActivity.java) y código Web (MQTT.js) para que ambos sistemas funcionen en paralelo sin desconectarse.

Host EMQX: h0bc12ce.ala.us-east-1.emqxsl.com
Puerto Android (TLS): 8883 (ssl://)
Puerto Web (WSS): 8084 (wss://.../mqtt)
Tópico Raíz: hogar/#

🔑 1. Reglas Clave en EMQX Cloud: ¿Por qué fallaba antes y cómo funciona ahora?

A. Diferencia de Puertos (8883 vs 8084)

Los navegadores web no pueden abrir sockets TCP puros por seguridad; obligatoriamente requieren WebSockets sobre TLS (wss://) en el puerto 8084. En cambio, Android nativo usa TCP con SSL (ssl://) en el puerto 8883 (aunque también soporta 8084). El puerto 8884 está cerrado o reservado para certificados de cliente mutuos, por eso daba connack timeout.

B. Client ID Único por Dispositivo

En el estándar MQTT, dos clientes no pueden usar el mismo CLIENT_ID al mismo tiempo. Si Android y la Web se conectan como android-device, el broker desconecta inmediatamente al anterior.

✅ Solución: Android usa "android-device" y la Web usa "android-device-web".

C. Autorización en EMQX Cloud

En el panel de EMQX Cloud (Access Control → Authentication / Authorization):
• Usuario: android-username
• Contraseña: android-username
• Permisos ACL: Permitir Publish & Subscribe al tópico hogar/# tanto para android-device como para android-device-web.

Parte 1 · Aplicación Móvil

🤖 Cómo Conectar en Android (Java)

Paho MQTT Android

Paso 1: Agregar dependencia en app/build.gradle

Se utiliza el fork mantenido hannesa2:paho.mqtt.android compatible con Android 12+ (API 31 a 36). 

dependencies {
    // Librería cliente MQTT para Android
    implementation 'com.github.hannesa2:paho.mqtt.android:3.3.5'
}

Paso 2: Permisos y Servicio en AndroidManifest.xml

MQTT corre en un servicio en segundo plano (MqttService). Si no se declara info.mqtt.android.service.MqttService dentro de <application>, la app nunca se conectará. 

<!-- Permisos necesarios para red y mantener viva la conexión -->
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.WAKE_LOCK" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />

<application ...>
    <!-- OBLIGATORIO: Servicio en segundo plano de la librería MQTT -->
    <service android:name="info.mqtt.android.service.MqttService" />
</application>

Paso 3: Configurar Credenciales y Cliente en MainActivity.java

Definimos la URL con ssl://...:8883 (TLS nativo) y wss://...:8084/mqtt como respaldo. Luego instanciamos MqttAndroidClient con Ack.AUTO_ACK para confirmar automáticamente los mensajes recibidos. 

private static final String MQTT_BROKER_URL =
    "ssl://h0bc12ce.ala.us-east-1.emqxsl.com:8883";
private static final String CLIENT_ID = "android-device";
private static final String MQTT_USERNAME = "android-username";
private static final String MQTT_PASSWORD = "android-username";

// En onCreate():
client = new MqttAndroidClient(
    getApplicationContext(),
    MQTT_BROKER_URL,
    CLIENT_ID,
    Ack.AUTO_ACK
);

Paso 4: Conectar al Broker y Escuchar Mensajes (MqttCallbackExtended)

Usamos MqttConnectOptions para enviar usuario, contraseña, reconexión automática y sesión limpia. Cuando connectComplete se dispara, nos suscribimos a hogar/#. Cada vez que llega un mensaje a cualquier subtópico de hogar/#, se ejecuta messageArrived. 

client.setCallback(new MqttCallbackExtended() {
    @Override
    public void connectComplete(boolean reconnect, String serverURI) {
        // Al conectar o reconectar, nos suscribimos a todos los tópicos del hogar
        subscribeToTopics();
    }

    @Override
    public void messageArrived(String topic, MqttMessage message) {
        String payload = new String(message.getPayload());
        // Importante: actualizar la interfaz dentro de runOnUiThread()
        runOnUiThread(() -> {
            appendToSubscriptionLog(topic, payload);
        });
    }

    @Override
    public void connectionLost(Throwable cause) { }
    @Override
    public void deliveryComplete(IMqttDeliveryToken token) { }
});

MqttConnectOptions options = new MqttConnectOptions();
options.setUserName(MQTT_USERNAME);
options.setPassword(MQTT_PASSWORD.toCharArray());
options.setAutomaticReconnect(true);
options.setCleanSession(true);

client.connect(options, null, new IMqttActionListener() {
    @Override
    public void onSuccess(IMqttToken asyncActionToken) {
        // Conexión exitosa
    }
    @Override
    public void onFailure(IMqttToken token, Throwable exception) {
        // Manejo de error
    }
});

Paso 5: Suscribirse (subscribe) y Publicar (publish)

El comodín # en hogar/# escucha todos los niveles (hogar/living/luz/set, hogar/alarma/set, etc.) con calidad de servicio QoS 1 (entrega garantizada al menos una vez). 

// 1. SUSCRIBIRSE AL TÓPICO RAÍZ
client.subscribe("hogar/#", 1, null, new IMqttActionListener() { ... });

// 2. PUBLICAR UN COMANDO (ej. encender luz)
MqttMessage message = new MqttMessage("on".getBytes());
message.setQos(1);
client.publish("hogar/living/luz/set", message, null, new IMqttActionListener() { ... });
Parte 2 · Navegador Web

🌐 Cómo Conectar en la Web (HTML + MQTT.js)

MQTT.js + Tailwind CSS

Paso 1: Importar Tailwind CSS y MQTT.js en el <head>

En el archivo index.html cargamos Tailwind CSS para el diseño responsivo en paralelo y el bundle oficial de mqtt.min.js que expone el objeto global mqtt en el navegador. 

<!-- Tailwind CSS para diseño de las 2 páginas en paralelo -->
<script src="https://cdn.tailwindcss.com"></script>

<!-- Cliente MQTT para navegadores (WebSockets) -->
<script src="https://unpkg.com/mqtt/dist/mqtt.min.js"></script>

<!-- Archivo local de credenciales -->
<script src="config.local.js"></script>

Paso 2: Configurar Puerto 8084 y Client ID en config.local.js

En EMQX Cloud, las conexiones WebSocket con TLS (wss://) usan el puerto 8084 y el path /mqtt. Además asignamos android-device-web para no colisionar con el android-device del teléfono. 

window.MQTT_CONFIG = {
  brokerUrl: "wss://h0bc12ce.ala.us-east-1.emqxsl.com:8084/mqtt",
  clientId: "android-device-web",
  username: "android-username",
  password: "android-username",
  topic: "hogar/#"
};

Paso 3: Iniciar la Conexión WebSocket (mqtt.connect)

Llamamos a mqtt.connect(brokerUrl, options). La librería abre un túnel WebSocket seguro y realiza el handshake MQTT enviando las credenciales. 

const client = mqtt.connect(
  "wss://h0bc12ce.ala.us-east-1.emqxsl.com:8084/mqtt",
  {
    clientId: "android-device-web",
    username: "android-username",
    password: "android-username",
    clean: true,           // Sesión limpia al conectar
    connectTimeout: 8000,  // Tiempo máximo de espera (8 seg)
    reconnectPeriod: 4000  // Reintento automático cada 4 seg
  }
);

Paso 4: Suscribirse y Actualizar el Monitor en Tiempo Real

Escuchamos el evento 'connect' para suscribirnos a hogar/#, y el evento 'message' para recibir cada cambio enviado desde Android o desde el propio panel web. 

// 1. Cuando el broker acepta la conexión (CONNACK):
client.on("connect", () => {
  setStatus("connected", "✅ Conectado (android-device-web)");
  // Suscripción con QoS 1 y nl: true (evita recibir eco duplicado propio)
  client.subscribe("hogar/#", { qos: 1, nl: true });
});

// 2. Cuando llega un mensaje desde Android o desde otro cliente:
client.on("message", (topic, payload) => {
  const texto = payload.toString();
  // Actualiza las tarjetas LED del Monitor y agrega la fila al Visor
  showMessage(topic, texto);
});

Paso 5: Publicar Comandos desde el Panel de Control Web

Cada botón del HTML tiene atributos data-pub-topic y data-pub-payload. Al hacer clic, se envía el mensaje al broker con client.publish() y se actualiza la vista paralela del Monitor al instante. 

<!-- Botón en HTML -->
<button data-pub-topic="hogar/living/luz/set" data-pub-payload="on">
  Encender
</button>

// Función de publicación en JavaScript:
function publishMessage(topic, payload) {
  // 1. Actualiza el Monitor local inmediatamente
  showMessage(topic, String(payload));

  // 2. Publica en EMQX Cloud con QoS 1 y retain: true
  if (client && client.connected) {
    client.publish(topic, String(payload), { qos: 1, retain: true });
  }
}
Flujo de Salida · Emisor (Publish)

📤 ¿Cómo el usuario ENVÍA información?

PUBLISH

En MQTT, enviar información se llama Publicar (Publish). El usuario envía un paquete con dos datos clave: el Tópico (Topic) (la dirección o canal, ej. hogar/living/luz/set) y el Payload (Mensaje) (el valor o comando, ej. on).

1️⃣ Desde la Página Web (Panel de Control):
  • Con los botones rápidos: Al pulsar Encender, Abrir, Activar o mover el Termostato, la web lee el tópico y el valor del botón y ejecuta client.publish(topic, payload).
  • Con el formulario personalizado: En la tarjeta "📤 Enviar comando personalizado", el usuario puede escribir cualquier tópico (ej. hogar/cocina/ventilador) y cualquier mensaje (ej. velocidad_2) y pulsar Publicar.
2️⃣ Desde la App Android:

Cuando el usuario toca un botón en el teléfono, el método publishWithConfirmation(topic, payload, msg) convierte el texto en bytes (payload.getBytes()), crea un objeto MqttMessage con calidad de entrega QoS 1 y lo envía al broker EMQX mediante client.publish(...).

Código exacto cuando el usuario envía un dato: 
// EN LA WEB (JavaScript - MQTT.js):
client.publish("hogar/living/luz/set", "on", { qos: 1, retain: true });

// EN ANDROID (Java - Paho MQTT):
MqttMessage message = new MqttMessage("on".getBytes());
message.setQos(1);
client.publish("hogar/living/luz/set", message, null, callback);
Flujo de Entrada · Receptor (Subscribe)

📥 ¿Cómo el usuario RECIBE información?

SUBSCRIBE

En MQTT, recibir información consta de dos pasos: primero Suscribirse (Subscribe) a un tópico (como hogar/#, donde # significa "todos los subtópicos dentro de hogar") y segundo Escuchar el Evento de Llegada que el broker empuja en tiempo real sin necesidad de recargar la página.

1️⃣ En la Página Web (Monitor y Visor de Suscripción):
  • Suscripción automática o manual: Al conectarse, la web se suscribe automáticamente a hogar/#. Además, el usuario puede agregar nuevos tópicos en la barra "+ Suscribir".
  • Recepción en vivo: Cuando Android (u otro usuario) publica algo, se dispara client.on("message", ...), que enciende los indicadores LED del Monitor y añade el registro con hora exacta en la consola del Visor de Suscripción.
2️⃣ En la App Android:

Al conectar, Android ejecuta client.subscribe("hogar/#", 1, ...). Cada vez que la Web o cualquier sensor publica un dato en hogar/..., se activa automáticamente el callback messageArrived(topic, message), mostrando un Toast emergente y agregando la línea al 📡 Visor de Suscripción inferior de la app.

Código exacto cuando el usuario recibe un dato: 
// EN LA WEB (JavaScript - MQTT.js):
client.subscribe("hogar/#", { qos: 1 });
client.on("message", (topic, payload) => {
  showMessage(topic, payload.toString()); // Actualiza Monitor y Visor
});

// EN ANDROID (Java - Paho MQTT):
client.subscribe("hogar/#", 1, null, callback);
@Override
public void messageArrived(String topic, MqttMessage message) {
  String dato = new String(message.getPayload());
  runOnUiThread(() -> appendToSubscriptionLog(topic, dato));
}

Paso 4: Suscribirse y Actualizar el Monitor en Tiempo Real

Escuchamos el evento 'connect' para suscribirnos a hogar/#, y el evento 'message' para recibir cada cambio enviado desde Android o desde el propio panel web. 

// 1. Cuando el broker acepta la conexión (CONNACK):
client.on("connect", () => {
  setStatus("connected", "✅ Conectado (android-device-web)");
  // Suscripción con QoS 1 y nl: true (evita recibir eco duplicado propio)
  client.subscribe("hogar/#", { qos: 1, nl: true });
});

// 2. Cuando llega un mensaje desde Android o desde otro cliente:
client.on("message", (topic, payload) => {
  const texto = payload.toString();
  // Actualiza las tarjetas LED del Monitor y agrega la fila al Visor
  showMessage(topic, texto);
});

Paso 5: Publicar Comandos desde el Panel de Control Web

Cada botón del HTML tiene atributos data-pub-topic y data-pub-payload. Al hacer clic, se envía el mensaje al broker con client.publish() y se actualiza la vista paralela del Monitor al instante. 

<!-- Botón en HTML -->
<button data-pub-topic="hogar/living/luz/set" data-pub-payload="on">
  Encender
</button>

// Función de publicación en JavaScript:
function publishMessage(topic, payload) {
  // 1. Actualiza el Monitor local inmediatamente
  showMessage(topic, String(payload));

  // 2. Publica en EMQX Cloud con QoS 1 y retain: true
  if (client && client.connected) {
    client.publish(topic, String(payload), { qos: 1, retain: true });
  }
}
