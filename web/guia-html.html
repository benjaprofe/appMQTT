Configuración del Navegador Web

Conexión de HTML y JavaScript con EMQX Cloud

Los navegadores web se conectan a MQTT mediante WebSockets Seguros (wss://) en el puerto 8084 usando la librería MQTT.js.

Broker URL: wss://h0bc12ce.ala.us-east-1.emqxsl.com:8084/mqtt
Client ID: android-device-web
Usuario: android-username
Contraseña: android-username
Tópico Raíz: hogar/#
1. ¿Por qué el puerto 8084 y no 8884?

En EMQX Cloud, el puerto 8084 es el canal abierto para WebSockets TLS (wss://.../mqtt). El puerto 8884 está cerrado o requiere certificado de cliente, causando connack timeout.

2. Client ID: android-device-web

Al usar un Client ID propio para la web (android-device-web) distinto del teléfono (android-device), ambos clientes pueden operar al mismo tiempo en paralelo.

3. Diseño Paralelo con Tailwind CSS

El archivo index.html divide la pantalla en dos columnas con grid-cols-1 lg:grid-cols-2: a la izquierda el Panel de Control y a la derecha el Monitor + Visor.

🛠️ Paso a Paso: Estructura del HTML y Conexión con MQTT.js

Paso 1: Cargar Tailwind CSS, MQTT.js y config.local.js en el <head>

index.html

No hace falta instalar Node.js para el navegador: importamos directamente el CDN de Tailwind CSS y el bundle de mqtt.min.js: 

<head>
  <meta charset="utf-8">
  <title>Sistema MQTT · Control y Monitor</title>
  <!-- 1. Tailwind CSS para los estilos modernos y el diseño en paralelo -->
  <script src="https://cdn.tailwindcss.com"></script>

  <!-- 2. Librería oficial MQTT.js para navegadores web -->
  <script src="https://unpkg.com/mqtt/dist/mqtt.min.js"></script>

  <!-- 3. Configuración de credenciales del broker -->
  <script src="config.local.js"></script>
</head>

Paso 2: Definir las credenciales en web/config.local.js

config.local.js

Guardamos los datos del broker en window.MQTT_CONFIG apuntando al puerto WebSocket TLS 8084: 

window.MQTT_CONFIG = {
  brokerUrl: "wss://h0bc12ce.ala.us-east-1.emqxsl.com:8084/mqtt",
  clientId: "android-device-web",
  username: "android-username",
  password: "android-username",
  topic: "hogar/#"
};

Paso 3: Conectar al Broker con mqtt.connect()

JavaScript

Al abrir la página o pulsar el botón Conectar, ejecutamos mqtt.connect(brokerUrl, options) y actualizamos el indicador de estado superior cuando llega el evento 'connect': 

function connectBroker() {
  client = mqtt.connect(brokerUrl, {
    clientId: "android-device-web",
    username: "android-username",
    password: "android-username",
    clean: true,
    connectTimeout: 8000,
    reconnectPeriod: 4000
  });

  // Se dispara cuando EMQX acepta la conexión
  client.on("connect", () => {
    setStatus("connected", "✅ Conectado (android-device-web)");
    // Nos suscribimos inmediatamente a todos los eventos del hogar
    client.subscribe("hogar/#", { qos: 1, nl: true });
  });

  // Se dispara si hay un error de red o credenciales
  client.on("error", (err) => {
    setStatus("error", "❌ Error: " + err.message);
  });
}
Flujo de Salida en la Web

📤 Cómo el usuario ENVÍA información (Publish)

client.publish()

Desde la Página 1: Panel de Control del HTML, el usuario tiene 3 formas de enviar información al broker MQTT (y que llegue al instante al teléfono Android):

1. Botones HTML con atributos data-pub-topic y data-pub-payload:

<!-- Botones en el HTML -->
<button data-pub-topic="hogar/living/luz/set" data-pub-payload="on">
  Encender
</button>
<button data-pub-topic="hogar/living/luz/set" data-pub-payload="off">
  Apagar
</button>

<script>
  // Escuchador para todos los botones de control
  document.querySelectorAll("[data-pub-topic]").forEach((btn) => {
    btn.addEventListener("click", () => {
      publishMessage(btn.dataset.pubTopic, btn.dataset.pubPayload);
    });
  });
</script>

2. Función publishMessage() que envía el paquete a EMQX:

function publishMessage(topic, payload) {
  const strPayload = String(payload);

  // 1. Actualiza la vista del Monitor en paralelo de inmediato
  showMessage(topic, strPayload);

  // 2. Envía el mensaje por WebSocket al broker EMQX Cloud
  if (client && client.connected) {
    client.publish(topic, strPayload, {
      qos: 1,       // Garantiza que el broker reciba el comando
      retain: true  // Guarda el último estado en el broker
    });
  }
}
Flujo de Entrada en la Web

📥 Cómo el usuario RECIBE información (Subscribe)

client.on("message")

En la Página 2: Monitor y Visor de Suscripción del HTML, la web mantiene una suscripción activa a hogar/#. Cuando alguien toca un botón en la App Android, el navegador recibe el paquete y actualiza tanto las tarjetas LED como la lista de mensajes.

1. Escuchar la llegada de mensajes con client.on("message"):

// Cada vez que EMQX envía un mensaje de un tópico suscrito:
client.on("message", (topic, payload) => {
  // payload llega como Uint8Array/Buffer, lo convertimos a texto
  const mensajeTexto = payload.toString();

  // Actualizamos las tarjetas del Monitor y el historial del Visor
  showMessage(topic, mensajeTexto);
});

2. Actualizar el Monitor LED y el Visor de Suscripción:

function updateMonitorAndControl(topic, payload) {
  const val = payload.trim().toLowerCase();
  const hora = new Date().toLocaleTimeString();

  if (topic === "hogar/living/luz/set") {
    const encendida = (val === "on");
    document.getElementById("mon-val-luz").textContent =
      encendida ? "Encendida" : "Apagada";
    document.getElementById("mon-time-luz").textContent =
      "Actualizado " + hora;
    // Enciende el borde y el LED verde en la tarjeta del Monitor
    styleMonitorCard("mon-card-luz", "mon-led-luz", encendida);
  }
  // ... lo mismo para puerta, alarma, tv y termostato
}
